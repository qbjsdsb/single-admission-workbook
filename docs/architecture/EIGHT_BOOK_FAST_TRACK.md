# 八册高速生产路线

目标不是“继续搭系统”，而是用最短路径把 224 份来源中的真实题目稳定变成四科学生练习册与教师解析册，共 8 册。

## 核心原则

生产优化只做三类事情：减少重复解析与重复人工判断；让互不依赖的来源、科目和验证步骤并行；把人工只留给真正存在歧义、冲突或视觉保真风险的条目。不得通过放宽答案、分值、来源、题目覆盖、富内容保真或出版 QA Gate 来换速度。

## 当前最快路径

### 1. 一次 intake，多次复用

原始资料只做一次指纹、格式转换和 Document AST 缓存。后续答案配对、分值、分类、复核与渲染都复用缓存；只有来源内容或解析器版本真正改变才失效。

### 2. 已支持科目先并行跑到底

英语和政治不再串行等待。对每科同时运行：已配对原卷/解析卷批量复核、未配对或混合来源的同源显式证据验证、已验证题目的分值绑定，以及配对来源的严格验证与跨来源分值佐证。

```bash
python scripts/run_fast_production.py build/private/intake \
  --subject english \
  --out build/private/production/english \
  --workers 4
```

政治把 `english` 改成 `politics`。内容型 blocker 会留在摘要中，不会因为某些题需要复核而让已经可靠的题重新解析。

### 3. 四科并行生产，不再“英语做完再做下一科”

- **英语**：优先形成第一套完整学生册/教师册，用真实全册暴露最后的成书问题。
- **政治**：复用现有 Candidate/Evidence/Verification 管线；重点补稳定章节 taxonomy 与材料题解析。
- **语文**：新增中文专用题型适配，先覆盖字音字形、现代文/古诗文题组、作文，再处理加点、下划线和扫描页。
- **数学**：走“结构 + 资产”双轨，文字题先入库；公式、图形、OLE/WMF/OMML 必须保留原始资产定位，视觉未核验前不降级成纯文本。

四条线可以同时推进；最终仍由统一 Occurrence Ledger 和八册 build Gate 收口。

## 困难页策略

默认顺序：原生 DOCX/PDF 结构解析 → 局部结构恢复 → 只对扫描/表格/公式/复杂版面难页启用候选解析器 → 多解析器不一致时保留原页证据并复核 → 实在无法可靠结构化的图形题允许以高质量源图块进入 rich node，避免为了结构化而损失题意。

候选工具只作为困难页适配器，不替换当前主流水线，也不因此增加常驻重依赖：

- PP-StructureV3：中文布局、表格、公式和阅读顺序候选恢复；
- MinerU：按页面难度选择轻/重路径，避免全库重模型推理；
- OCRmyPDF：仅用于确需 OCR 的页，优先轻量配置，不得使用会静默漏页的提速策略。

是否接入以真实代表页 A/B 基准为准，至少记录准确率、公式/图形保真、阅读顺序和耗时。

## 正式两册 Gate

每科正式成书前必须同时满足：每个来源文件有明确去向；每次真实题目出现进入 Occurrence Ledger 或有明确非题/伪影理由；完全重复题可一次排印但保留全部来源 occurrence；固定答案有可追溯证据且无冲突；分值证据明确；每题已分章且题组原子；教师解析通过相应 Gate；加点、下划线、公式、表格、图形、图片完成保真检查；学生版无答案/解析泄漏；全书 A4、目录、书签、页码、缺字、溢出、空页、彩色与灰度检查通过。

最终八册再做一次全局 Gate：四科 source occurrence 100% accounted，八份书目覆盖与 Canonical 一致。

除非新问题直接阻塞以上路径，否则不新增微服务、消息队列、数据库、Web 管理后台或新的抽象层。
